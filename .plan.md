# Plan: Loading Animation with STEG Logo

## Context
After login, the dashboard renders instantly (subnav + filters) but then blocks silently on `build_forecast()` with zero loading feedback — the page appears frozen. All 4 `@st.cache_data` calls have `show_spinner=False`. Users need visual confirmation the page is working.

## Approach: Full-viewport CSS overlay + `st.empty()` placeholder

### 1. `ui/theme.py` — Add `steg_loading_css()` function

New function that injects a CSS class `.steg-loading-overlay` with:
- Full-viewport覆盖 (`position: fixed; inset: 0; z-index: 9999`)
- Same blue gradient as login page (`linear-gradient(135deg, #0b3d91, #1b5ec1)`)
- Centered STEG logo (inlined via `asset_uri("assets/steg_logo.png", "image/png")`)
- Pulsing animation: `@keyframes steg-pulse` — opacity 0.6→1.0, scale 0.95→1.05, 1.5s ease-in-out infinite
- "Chargement..." text below logo with fade-in
- Flexbox centered layout

Call `steg_loading_css()` inside `render_css()` so it's available on every page (but only activated by adding the `.steg-loading-overlay` div).

### 2. `app.py` — 1 line

After `st.session_state["user"] = user` (line 148), add:
```python
st.session_state["dashboard_loaded"] = False
```

### 3. `pages/dashboard.py` — Show/hide overlay

In `render()`:
1. Before the first fragment, create `loading_placeholder = st.empty()`
2. Render the overlay HTML into it (a `<div class="steg-loading-overlay">` containing the base64 logo + "Chargement..." text)
3. After `production_dashboard()` returns (first engine call completes), call `loading_placeholder.empty()` to remove it

On subsequent reruns (cache hit), `build_forecast` returns instantly, so the overlay flashes briefly or not at all. The `st.empty()` is cleared on the same run.
